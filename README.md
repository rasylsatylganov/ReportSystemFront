# Фронтенд универсальной системы отчётности

Это пустая основа для пошаговой разработки. Главное меню расположено сверху,
рабочая область пустая. В правом углу — переключение светлой и тёмной темы,
как в примере. Нажатие на название возвращает на главную страницу.
Список пунктов меню пока пустой.

Авторизации, пользователей, проверки прав и запросов к backend нет.
Приложение можно запускать без Java-приложения и Oracle.

## 1. Первый запуск в Windows

Установите Node.js 22.12 или новее (например, ветку 22 или 24).
Node.js включает npm — инструмент установки зависимостей и запуска команд.
После установки перезапустите терминал IntelliJ IDEA.

Откройте папку `reporting-frontend` в IDEA и запустите терминал в ней:

```powershell
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run dev
```

Откройте http://localhost:5173 в браузере. Остановка сервера — Ctrl+C.
`npm.cmd` вместо `npm` позволяет работать в PowerShell без изменения
политики выполнения скриптов. В Git Bash можно использовать обычное `npm`.

`npm ci` устанавливает версии из package-lock.json в папку node_modules.
Исходники находятся в src. Не редактируйте файлы в node_modules.
Если порт 5173 занят, остановите другое приложение или измените port
в vite.config.ts. strictPort не позволяет незаметно сменить адрес.

## 2. Команды проекта

| Команда | Назначение |
|---|---|
| `npm.cmd run dev` | Запустить сервер разработки |
| `npm.cmd run type-check` | Проверить типы TypeScript и Vue |
| `npm.cmd run build` | Проверить типы и собрать приложение в dist |
| `npm.cmd run preview` | Открыть ранее собранную версию на http://localhost:4173 |

После изменения и сохранения исходников сервер разработки обновляет страницу.
Для просмотра dist сначала выполните build. preview — локальная проверка,
а не сервер для промышленной эксплуатации.

| 5 | `src/core/components/layout/AppTemplate.vue` | Общий каркас страницы |

`public` содержит статические файлы, которые копируются без обработки.

## 4. Как понимать Vue-файл

Компонент — элемент интерфейса, который объединяет код, разметку и стили.
Файл с расширением .vue может содержать:

- `<script setup lang="ts">` — переменные, функции, импорты на TypeScript;
- `<template>` — разметку интерфейса;
- `<style>` — стили (в этом каркасе общие стили собраны в styles.scss).

`{{ value }}` выводит значение в разметке.
`:model="APP_MENU"` передаёт JavaScript-значение в параметр компонента.
`@click="toggleDarkMode"` вызывает функцию по нажатию.
`v-if` показывает элемент по условию.
`ref(false)` создаёт изменяемое значение: Vue обновит интерфейс при его изменении.
В коде script значение ref читается через `.value`, в template — без `.value`.
`slot` — место, в которое родительский компонент передаёт содержимое.
`#start` и `#end` — именованные места внутри Menubar.

Все компоненты импортируются явно: автоматической регистрации компонентов нет.
Это упрощает понимание того, откуда взялся Button, Menubar или RouterView.

## 5. Куда добавлять следующие части

- `src/app/pages` — страницы, открываемые по URL;
- `src/app/router/menu.ts` — пункты меню;
- `src/app/router/index.ts` — маршруты этих страниц;
- `src/modules` — будущие функциональные разделы, например справочники;
- `src/core/services` — будущие обращения к Java API;
- `src/core/stores` — будущие общие хранилища Pinia;
- `src/core/components` — повторно используемые компоненты.

Три последние пустые папки сохранены файлами .gitkeep.
Когда начнём реализацию, будем добавлять по одной странице и разбирать её код.
Пример пункта меню приведён в комментарии menu.ts и сейчас не выполняется.
Новую страницу нужно зарегистрировать в router/index.ts; одного пункта меню
для создания страницы недостаточно.

## 6. Библиотеки

Версии основных библиотек взяты из присланного package-lock.json и закреплены
в новом package.json. Lock-файл нового проекта соответствует его зависимостям.

| Библиотека | Назначение |
|---|---|
| Vue 3 | Компоненты и обновление интерфейса |
| TypeScript | Типы переменных и параметров |
| Vue Router | Переключение страниц |
| PrimeVue 4 | Готовые элементы интерфейса |
| @primeuix/themes | Тема Aura |
| PrimeIcons | Иконки |
| PrimeFlex | CSS-классы компоновки, как в примере |
| Pinia | Общие хранилища данных; подключена, но пока не используется |
| Sass | Обработка SCSS |
| Vite | Сервер разработки и сборка |

Графики, Excel, валидация форм и HTTP-клиент из большого примера пока не нужны.
Их можно добавить при реализации соответствующих функций. Webpack, Docker
и GitLab CI в этот локальный каркас не переносились. Адреса и настройки
окружений другого проекта не копировались.

## 7. Связь с backend

Проект frontend самостоятельный и не является Maven-модулем.
Его можно хранить рядом с корневым pom.xml backend или в отдельной папке.
Доступ к REST API добавим на следующем этапе вместе с первой страницей.
Сейчас нет ни настройки прокси API, ни автоматических обращений к localhost:8080.

В браузерном приложении никогда не нужны логин и пароль Oracle: к БД обращается
Java backend. Переменные VITE_* также попадают в клиентскую сборку.
